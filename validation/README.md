# Portal JSON parser

Rewritten from `geant-config-generator/tests/geant4/TestEm12-DPK/parser.py`
(old `gts.BaseParser` + PyROOT API) for the module-level `metadata()`/`parse()`
API that `ci-workflows/validation/export.py` actually calls, reading the ROOT
histogram with `uproot` instead of PyROOT (no PyROOT on the CI runner),
matching the pattern established by `LowEFrag`.

`config.json` selects 4 concrete macros generated by substituting
`geant-config-generator/tests/geant4/TestEm12-DPK/template.conf` with one row
of `params.conf` (physics list `dna_opt2`, `FLUCT=true`, `CUT=2 nm`,
`MATERIAL=G4_WATER`) across the 4 reference beam energies (10, 15, 100,
1000 keV). The `dna.mac`/`run01.mac`/`run02.mac`/`berger.mac`/`vis.mac` files
originally found in `geant-validation-tests/src/TestEm12` are kept for
reference but are **not** the macros this parser was written against — they
predate (and don't match) the `output.root`/histogram-8 format `parser.py`
expects; only the 4 generated macros write that format. `params.conf`'s
other two physics lists (`dna_opt4`, `dna_opt6`) and `FLUCT=false` are not
included — generate more macros the same way if needed.

Histogram `"8"` ("normalized edep profile", `d(E/E0)/d(r/r0)` vs `r/r0`) is
read from `output.root`; the filled-bin trimming (`FindFirstBinAbove`/
`FindLastBinAbove` in the original) is reproduced by scanning for the first
and last non-zero bin. `HistoManager.cc` sets no asymmetric error option on
this histogram, so (as with the original's `GetBinErrorUp`/`GetBinErrorLow`
on the same histogram) the up/low statistical errors are identical — read
once via `uproot`'s single `errors()`.
